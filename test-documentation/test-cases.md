## Test Case Structure

Each test case includes the following information:

| Field | Description |
|-------|-------------|
| Test Case ID | A unique identifier assigned to the test case |
| Requirement ID | The requirement covered by the test case |
| Module | The application area being tested |
| Test Scenario | A description of the functionality being verified |
| Preconditions | Conditions that must be met before testing |
| Test Data | The data required to execute the test |
| Test Steps | Step-by-step test execution instructions |
| Expected Result | The result the application should produce |
| Actual Result | The result observed during execution |
| Status | The test execution result |
| Priority | The importance of executing the test case |

## Testing Approach

The test cases were designed to validate:

- Successful user workflows
- Invalid user input
- Required-field validation
- Error messages
- Boundary conditions
- Unusual user behaviour
- Business-critical functionality
- Application navigation
- User-session behaviour
